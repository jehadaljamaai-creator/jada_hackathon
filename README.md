# منصة تحكيم جادة ثون

موقع واحد يُستخدم في كل هاكاثونات جادة 30:

| الصفحة | الرابط | لمن |
|---|---|---|
| صفحة المحكّم | `…/#j-رمز-المحكّم` | لكل محكّم رابط خاص باسمه، بلا تسجيل دخول |
| النتائج المباشرة | `…/#live` | شاشة القاعة والجمهور |
| الفائزون | `…/#winners` | شاشة إعلان الفائزين (كشف تدريجي من الثالث إلى الأول) |
| الإدارة | `…/#admin` | المنظّمون فقط (بريد وكلمة مرور) |

الموقع ملفات ثابتة تُستضاف مجاناً على **GitHub Pages**، والبيانات محفوظة في **Supabase** (قاعدة بيانات مجانية).

---

## الإعداد لأول مرة (حوالي 15 دقيقة)

### 1) قاعدة البيانات على Supabase
1. أنشئ حساباً مجانياً على [supabase.com](https://supabase.com) ثم **New project** (اختر أقرب منطقة، مثل Frankfurt أو Mumbai، واحفظ كلمة مرور قاعدة البيانات).
2. من القائمة الجانبية افتح **SQL Editor ← New query**، والصق محتوى الملف [`supabase/schema.sql`](supabase/schema.sql) كاملاً، ثم اضغط **Run**.
3. أنشئ حساب المنظّم: **Authentication ← Users ← Add user ← Create new user**، اكتب بريدك وكلمة مرور، وفعّل **Auto Confirm User**.
4. اجعل هذا البريد منظّماً: في **SQL Editor** شغّل:
   ```sql
   insert into public.admins (email) values ('بريدك@example.com');
   ```
   كرّر السطر لكل منظّم إضافي (بعد إنشاء حسابه في الخطوة 3).
5. أغلق التسجيل العام: **Authentication ← Sign In / Providers** وألغِ تفعيل **Allow new users to sign up**.

### 2) ربط الموقع بقاعدة البيانات
من **Project Settings ← API** انسخ **Project URL** و **anon public key**، وضعهما في الملف [`config.js`](config.js):
```js
window.JADA_CONFIG = {
  SUPABASE_URL: 'https://xxxx.supabase.co',
  SUPABASE_ANON_KEY: 'eyJ...'
};
```
مفتاح `anon` مصمّم ليكون عاماً؛ الصلاحيات محمية داخل قاعدة البيانات.

### 3) النشر على GitHub Pages
في المستودع: **Settings ← Pages ← Build and deployment**، اختر **Deploy from a branch**، والفرع `main` والمجلد `/ (root)`، ثم **Save**. بعد دقيقة يظهر رابط الموقع (مثل `https://اسمك.github.io/jada-hackathon/`).

## التشغيل في كل هاكاثون

1. **قبل الفعالية:** افتح `#admin` وسجّل الدخول ← **+ هاكاثون جديد** ← الاسم والمدينة والتاريخ، المعايير والأوزان (مجموعها 100%)، المشاريع، وعدد المحكّمين وأسماؤهم ← **إنشاء الهاكاثون** ← **جعله الهاكاثون النشط**.
2. **روابط المحكّمين:** في قسم لجنة التحكيم اضغط **نسخ روابط جميع المحكّمين** وأرسل لكل محكّم رابطه.
3. **بدء التحكيم:** غيّر **حالة التقييم** إلى «التقييم مفتوح» واحفظ.
4. **أثناء التحكيم:** اعرض `#live` على شاشة القاعة (تتحدث كل 4 ثوانٍ). لإخفاء الترتيب عن الجمهور حتى الإعلان ألغِ «إظهار الترتيب للجمهور».
5. **الإعلان:** غيّر الحالة إلى «التقييم مغلق»، اعرض `#winners` على الشاشة، ومن جهازك (مسجّلاً الدخول) افتح `#winners` واضغط **اكشف المركز الثالث** ثم الثاني ثم الأول.
6. **بعد الفعالية:** من الإدارة نزّل **الترتيب** و**كل التقييمات** بصيغة CSV.

## طريقة الحساب
- كل محكّم يقيّم كل معيار بشريط من 1 إلى 5 (أو 10).
- الدرجة من 100 = مجموع (متوسط المحكّمين للمعيار ÷ أعلى درجة × وزن المعيار).
- كسر التعادل: عدد أصوات «جدير بالفوز» ثم الأقل تفاوتاً بين المحكّمين؛ التعادل التام يُحال للجنة.
- تنبيه للجنة يظهر إذا تغيّر ترتيب الثلاثة الأوائل بعد توحيد مقاييس المحكّمين (لأن بعضهم أكثر تشدداً).

## الأمان والخصوصية
- الزوار لا يقرؤون الجداول مباشرة؛ يرون فقط ملخص النتائج، وأسماء الفائزين بعد كشفها.
- المحكّم يرى تقييماته فقط، ولا يحفظ إلا والتقييم مفتوح، وبقيم صحيحة ضمن المقياس.
- رابط المحكّم يعمل كمفتاح دخول؛ لا يُنشر علناً. حذف المحكّم يلغي رابطه وتبقى تقييماته محسوبة.
- لا تضع بيانات المحكّمين أو التقييمات في هذا المستودع؛ مكانها قاعدة البيانات.

## ملاحظات
- مشاريع Supabase المجانية تتوقف بعد أسبوع دون استخدام؛ افتح لوحة Supabase واضغط **Restore** قبل الفعالية بيوم.
- لتحديث قاعدة البيانات بعد تعديل `schema.sql` شغّله مرة أخرى؛ لا يحذف البيانات.
